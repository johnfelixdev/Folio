# Folio

**A native macOS PDF editor that works entirely on your Mac.**

[Español](README.es.md)

Folio is a desktop PDF editor written in Swift 6 and SwiftUI. Documents are
processed locally. The app bundle built by `Scripts/build-app.sh` is
sandboxed and signed without the network entitlement, so it cannot open
network connections. There is no telemetry, no analytics and no updater.
Where you save your files, a folder synced to the cloud for instance, is up to you.

> **Status: phase 1 of 4, in progress.** Pages can already be organised and
> saved. Annotation, text editing and forms come in later phases (see the
> [roadmap](#roadmap)). The interface is currently in Spanish only.

## What it does today

- **Open, create and save PDFs.** The app is built on `DocumentGroup` and
  `ReferenceFileDocument`, so autosave, versions, *Revert* and the "Edited"
  mark in the title bar come from the system's own document handling.
- **Reading view** with a thumbnail strip. Picking a thumbnail jumps to that page.
- **Light table.** A full-window grid of pages. Drag one or several pages to
  reorder them, or drop other PDF files onto the grid to merge them in, in
  the order you dropped them. Pages move only within their own document.
- **Rotate and delete** the selected pages.
- **Undo and redo every operation**, through the system ⌘Z.
- **Restricted PDFs.** Folio detects documents that open freely but forbid
  printing, copying or editing, and can rebuild them without those flags,
  keeping the title, author and bookmarks. It never guesses or cracks a
  password: a PDF that needs a password to *open* stays closed. Use this
  feature only on documents whose rights you hold or that you are
  authorised to modify, as the law that applies to you permits.
- **Inspector** with the page count and the protection state.

Splitting and extracting pages are implemented and tested in the core
(`ExportService`), but nothing in the interface calls them yet.

## Architecture

```
SwiftUI interface  (FolioApp)
        │  emits commands
        ▼
Document + undo    (FolioDocument, PageCommand)
        │
        ▼
PDFEngine protocol ← PDFKitEngine
```

- **Edits to the PDF go through the `PDFEngine` protocol.** Outside the
  engine, only the reading canvas imports PDFKit, to host the system's
  `PDFView`; a test (`ArchitectureTests`) keeps it that way. PDFKit cannot
  edit existing text, so phase 3 needs a second engine (PDFium or MuPDF).
  The protocol is where it will plug in. Today the document and a few
  commands still create `PDFKitEngine` directly, so phase 3 will also have
  to inject the engine there.
- **Every edit is a command that returns its own inverse**, so undo replays
  operations instead of keeping a copy of the document per step.
- **Pages get a stable identity (UUID) that survives reordering**, so
  moving or rotating a page only redraws the thumbnails that actually changed.
- **Saving needs no work on the main thread.** The system asks for the
  document's bytes on a background queue while the main thread waits for the
  save, so the bytes are refreshed on the main thread after every change and
  the save only reads them.
- **Inserting pages is all or nothing.** Every page is parsed before the
  first one goes in, and dropping several files is a single undo step.

## Requirements

- macOS 26 or later
- Swift 6 toolchain (Xcode or the Command Line Tools)

There are no external dependencies.

## Build and run

```bash
swift build
swift test
./Scripts/build-app.sh   # assembles build/Folio.app, sandboxed and signed ad-hoc
open build/Folio.app
```

No `.xcodeproj` and no asset catalogue: the whole app builds with
`swift build` and the Command Line Tools. Xcode can still open
`Package.swift` for previews and debugging. If there is no
`Scripts/icon-source.png`, the build script generates a placeholder icon.

## Tests

111 tests in 13 suites, using Swift Testing. Encrypted and restricted PDFs
are generated by fixtures at test time with CoreGraphics, and read back
with CoreGraphics too, so no PDF files are checked in and PDFKit never
grades its own output.

## Known limitations

- Undoing a page deletion brings the page back, but not the bookmarks that
  pointed to it.
- After deleting or undoing, the reading view keeps its position by page
  number, so it may show the neighbouring page.
- Splitting and extracting are not in the interface yet.
- The interface is in Spanish only.
